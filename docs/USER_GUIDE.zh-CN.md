# NetWright 使用指南

> NetWright 是一个**独立的网络工程师工作台**：设备清单 → 资产盘点 → 意图下发 →
> 批量巡检 → 配置生成 → 日常工具，全部在一个程序里。支持 Windows 单文件 exe 免安装运行。

## 0. 五分钟实操 Demo（新用户从这里开始）

### 方式零：一键演示数据（30 秒，最省事）

右上角 **「? 引导」→「载入演示数据」**（或「设备清单」空状态里的「① 载入演示数据」）：

- 自动写入 7 台演示设备（192.0.2.x 文档网段）+ 6 条台账链路，**不会连任何真实地址**
- 拓扑立刻有形状，事件页、概览 KPI 立刻有数字
- 随时可「清除演示数据」（按备注识别，只删演示设备，不动你自己的）

下面 5 个 Demo 是**带真实操作细节**的版本，建议先看一遍再上手。

仓库自带示例台账 [`docs/demo_ledger.csv`](demo_ledger.csv)（7 行，含 6 条链路与一台 Telnet 设备，
192.0.2.x 文档网段 + 演示密码 `Demo@123`）。跟着下面 5 个 Demo 走一遍，
就能体验全部核心功能。

### Demo 1 · 导入台账 → 自动生成拓扑（2 分钟）

1. 启动 NetWright → 「设备清单」页 → 点「导入 CSV…」
2. 选择仓库里的 `docs/demo_ledger.csv`
3. 观察：导入 5 台设备，**没有弹任何告警**
4. 「控制器」页 → 「拓扑」Tab → 点「从设备清单自动发现拓扑」——
   即使不连设备，**台账里的对接关系（核心A↔核心B↔汇聚C↔接入D…）已经以虚线呈现**
5. 点 ☰ 折叠侧栏，看看 64px 图标模式

> 试试把 `demo_ledger.csv` 里某行改成 `protocol,telnet` 再重新导入——
> 该设备的接入协议自动变为 Telnet。

### Demo 2 · 意图下发（Dry-Run → 确认 → 审计，3 分钟）

1. 「控制器」页 → 「意图下发」Tab
2. 意图类型选「VLAN 部署」，VLAN 列表填 `100,200`，描述填 `Demo`
3. 目标设备选「(全部设备)」→ 点 **① Dry-Run 预览**
4. 观察预览区：同一份意图被翻译成**华为 VRP / H3C Comware / 思科 IOS** 三种命令
5. 点 **② 确认下发**（弹窗确认后走 SSH 真实下发；演示环境连不上会显示失败——
   这正说明流程正确：命令已生成，只是设备不可达）
6. 「刷新审计」——下发的每条命令都记录在 `netwright_audit.log`（无密码）

### Demo 3 · 批量巡检 + 趋势图（2 分钟）

1. 「批量巡检」页 → 勾选目标设备 → 方案选「标准巡检」→ 点「开始巡检」
2. 演示环境设备不可达：全部显示 `○ 不可达`（灰）；真实环境会看到
   ✓ 正常 / ▲ 告警 / ✖ 失败 三种状态
3. 点「导出报告」保存 HTML——双击浏览器打开，含逐命令原始输出
4. 底部「📈 趋势」：每跑一轮巡检，告警数/失败数会多一个数据点，
   多轮之后即可看出网络健康趋势

### Demo 4 · 工具箱三连（1 分钟）

1. 「工具箱」→ 子网计算：输入 `10.0.0.0/8` 计算，再输入 VLSM 主机数
   `100, 50, 20, 5` 点划分——四个子网自动从大到小排布
2. 端口扫描：目标填 `127.0.0.1`，端口填 `22,80,443,830`，扫描本机
3. 在线检测：目标填 `127.0.0.1-3`（末八位简写写法），体验区间展开

### Demo 5 · 配置生成（3 分钟）

1. 「配置生成」页 → 厂商筛「华为」→ 模板选「VLAN 基础」
2. 点「载入清单设备」——按模板变量自动生成参数表骨架
3. 补全变量值（模板头注释里列了每个变量的含义）
4. 点「生成到目录…」——打开输出目录，每台设备一个 .cfg；
   故意删掉某行的 hostname 再生成一次——**报错拦截，绝不产出坏配置**

### Demo 6 · 配置备份与漂移（2 分钟，v3.12+）

> 需要一台能 SSH/Telnet 登录的设备。演示数据是 192.0.2.x 假地址，会提示"连接失败"——
> 但失败提示本身也值得看一遍（v3.13 起是人话 + 下一步建议）。

1. 「设备清单」选中设备 →「🗄 备份配置」，第一次写入一份快照
2. 再点一次：提示 **无变化**（sha256 相同不重复落盘）
3. 手动在设备上加一条配置，再备份 → 提示"已更新"
4. 「🗂 备份历史」→ 右侧自动显示最近两次的 **unified diff**（`+/-` 着色）
5. 点「与现网对比」：不用先备份，直接看"现在和上次快照差在哪"；
   有差异会在事件页出现一条 `config.drift` 告警
6. 备份落在 `backups/<设备>/*.cfg`，可直接用资源管理器打开核对

## 1. 安装与启动

### 方式一：exe（推荐）

从 Releases 下载 `NetWright.exe`，双击即用（无需 Python）。
建议把它放在一个独立目录，数据文件会生成在同目录下。

### 方式二：源码运行

```bash
pip install paramiko        # 唯一运行依赖（SSH 巡检；不装也能用其余模块）
python main.py              # Python 3.10+
```

### 打包自己的 exe

```bash
pip install pyinstaller pillow
pyinstaller NetWright.spec --noconfirm
# 产物：dist/NetWright.exe
```

## 2. 界面总览

v3.9 起界面换成**控制器控制台**布局（对齐 OpenDaylight DLUX 一类 SDN 控制台）：

```
┌──────────────────────────────────────────────────────────────┐
│ ☰  NetWright SDN │ 当前页面          就绪  ● 控制器在线 时间 │ 52px 深色顶栏
├────────────┬─────────────────────────────────────────────────┤
│ 控制器      │  面包屑 / 标题 / 说明              [动作按钮]   │
│  概览       │  ┌───────────────────────┐  ┌──────────────┐  │
│  拓扑       │  │ 白卡片：画布 / 表格    │  │ 白卡片：侧栏 │  │
│  意图与策略 │  └───────────────────────┘  └──────────────┘  │
│  事件       │                                                 │
│ 资源 / 运维 │  浅色内容区（#F5F7FA）+ 8px 网格留白            │
└────────────┴─────────────────────────────────────────────────┘
```

- 顶栏：品牌 + 当前页面、右侧「就绪」状态、控制器在线指示灯、时钟、主色、明暗切换
- 顶栏右侧还有 **「自动 10s」勾选框**（默认开）与 **「? 引导」** 按钮
- 顶栏会显示 **上次刷新时间**（如 `19:42:07`），数字不动时先看这里
- 快捷键：`F5` 刷新当前页、`Ctrl+H` 打开引导、`Ctrl+1…9` 切换工作区、`Esc` 关闭弹窗
- 侧栏 224px，分「控制器 / 资源 / 运维」三组；点 ☰ 折叠成 64px 图标条（设置里记住）
- 明暗模式下**顶栏与侧栏都保持深色**，只切换内容区与主色 —— 这是控制台类产品的通行做法
- 所有配置/清单/审计/控制器快照文件保存在 exe（或源码根目录）下

### 2.1 拓扑工作区（控制器主视图）

- 链路两种来源：**LLDP 实测（实线）** 与 **台账导入（虚线）**；同一对端口被 LLDP 证实后
  会自动从虚线升级为实线
- 三种布局：力导向（默认）/ 环形 / 分层（BFS 按度数从核心铺开）
- 画布交互：滚轮缩放、拖拽平移、单击节点在右侧检查器看厂商/纳管/度数/邻居端口
- 右上角「从设备发现」按设备清单并发采集 LLDP/CDP，结果并回控制器图
- 底部图例只显示当前图里真实存在的厂商与链路类型

### 2.2 事件工作区

- 事件流：拓扑变更、策略编译、南向命令失败等，按级别着色，支持「仅告警 / 仅严重」过滤
- 南向通道：每种协议的**能力位**与依赖就绪状态（缺 ncclient/os-ken 会显式标「缺依赖」）
- 下发审计：最近 30 条真实下发记录（不含密码）

### 2.3 控制器内核（netwright.sdn）

| 模块 | 作用 |
|---|---|
| `sdn/events.py` | 线程安全事件总线（订阅 / 环形历史 / 严重度） |
| `sdn/model.py` | 图模型：节点、端口、链路去重与统计 |
| `sdn/policy.py` | 意图 → 策略编译（命令 + 风险等级，不连设备） |
| `sdn/store.py` | 控制器状态仓库（图 + 策略 + 统计，可持久化） |
| `sdn/southbound/` | 南向适配器：CLI 实装，NETCONF / OpenFlow / RESTCONF 骨架 |
| `sdn/nbapi.py` | 北向 REST v2 路由 |

> 南向骨架的约定：**能做的说能做，做不了的当场报错**。NETCONF/OpenFlow 适配器在缺依赖时
> `available=False`，调用 `run_commands`/`program_flows` 直接抛 `UnsupportedOperation`，
> 不会静默返回空结果让上层误以为下发成功。

### 2.5 设置页（v3.14）

左侧「系统 → 设置」集中放**会影响运行**的几项：

| 项 | 说明 | 生效方式 |
|---|---|---|
| REST 端口 | 北向服务端口（默认 8899） | **需要重启程序** |
| Syslog / SNMP Trap 端口 | 事件源监听端口（默认 5140 / 1162） | 保存后立即按新端口重启监听 |
| 备份保留份数 | 每台设备保留多少份快照（2-500） | 下一次写入快照时生效 |
| 自动刷新 | 每 10 秒刷新当前页 | 立即生效，与顶栏勾选同步 |

校验失败会明确指出是哪一项不合法（例如"保留份数必须在 2-500 之间"），不会静默保存半个配置。
### 2.4 面向小白的设计（v3.10）

这些不是花架子，都是为了"第一次打开不懵"：

| 设计 | 解决什么 | 在哪 |
|---|---|---|
| **一键演示数据** | 没设备时界面全是空的，不知道从哪下手 | `? 引导` / 设备清单空状态 |
| **引导面板** | 不想读文档，只想快点看到东西 | 顶栏「? 引导」或 `Ctrl+H` |
| **空状态三选一** | "没有设备"不再是一句冷冰冰的提示，而是三条路 | 设备清单 / 概览 |
| **自动刷新 10s** | 盯着页面等数字变化，以为程序卡了 | 顶栏勾选框（可关）+ `F5` |
| **连接测试** | 地址/端口/凭据到底哪一步不通 | 设备清单「🔌 测试连接」 |
| **拓扑搜索 / 仅纳管** | 几十台设备时找一台 | 拓扑页右上角 |
| **人话错误提示** | 报错说"请看日志"等于没说 | 设备清单（连接/备份）、运行档案（下发/校验/回滚）、巡检详情统一翻译 |

## 3. 设备清单（台账）

所有模块共用的设备与凭据中心。**密码经 Windows DPAPI 加密落盘**（当前用户可解，
换电脑/换用户无法解密——属预期安全行为）。

### 添加设备

点「＋ 添加设备」，在右侧抽屉中填写：

| 字段 | 必填 | 说明 |
|---|---|---|
| 地址 | ✅ | 管理 IP |
| 端口 | ✅ | 默认 22 |
| 厂商 | ✅ | 华为 VRP / 新华三 / 思科 / 锐捷 / MikroTik / VyOS / SONiC / Linux / 华为 AC / 新华三 AC / 思科 WLC / 通用 |
| 接入协议 | ✅ | ssh（默认）/ telnet |
| 用户名 / 密码 | | SSH/Telnet 登录凭据 |
| 名称 / 备注 | | 显示名与备注 |

字段级校验：地址为空、端口非 1-65535 会**在输入框下方红字提示**，不会误存。

### CSV 批量导入（台账）

点「导入 CSV…」，支持以下列（首行表头，中英文列名均可识别）：

```csv
host,port,vendor,protocol,username,password,hostname,note,local_intf,peer_device,peer_intf
192.0.2.11,22,huawei,ssh,admin,P@ss,核心A,,GE0/0/24,核心B,GE0/0/24
192.0.2.12,22,huawei,ssh,admin,P@ss,核心B,,GE0/0/24,核心A,GE0/0/24
192.0.2.21,23,h3c,telnet,admin,P@ss,汇聚C,,GE1/0/48,核心A,GE0/0/1
```

- **protocol**：ssh / telnet（**重启后不会丢**，v3.10 修复过这个 bug）
- **local_intf / peer_device / peer_intf**（可选）：填写后自动生成**台账拓扑链路**，
  在「拓扑」工作区中以虚线呈现（LLDP 自动发现为实线，二者叠加）
- **同一台设备可以写多行**：每行描述一条链路即可，重复的设备不会被重复添加，
  链路会全部收下（导出时也只保留一台）
- 纯重复行（没有链路信息）会提示"已存在，跳过"；厂商无法识别按 generic 处理

### 导出 CSV

「导出 CSV」**默认不含密码**——导出物经常被随手发到群里或贴进工单。
需要完整备份凭据时请直接复制 `netwright_devices.json`（密码是 DPAPI 密文）。

### 连接测试（排障第一步）

选中设备（或多选）→「🔌 测试连接」：**只做 TCP 端口连通性**，几秒出结果：

- `✓ 主机:端口 端口可达` → 网络通，问题在账号/协议/设备限制
- `✖ 主机:端口 不可达` → 路由/ACL/端口写错

> 端口可达 ≠ 登录成功。真正的登录验证在「批量巡检」里（会走 SSH/Telnet 认证）。

### 配置备份与差异（v3.12）

选中设备（不选则全部）→「🗄 备份配置」：

- 每台设备一份目录：`backups/<设备名>/<时间戳>.cfg`，可以直接用资源管理器打开
- **内容没变不会重复落盘**（按 sha256 判断），所以每天跑一次也不会堆垃圾
- 默认保留最近 **30 份**（`ConfigBackup(keep=...)` 可调）
- 备份结果会区分「已更新 / 无变化 / 失败」，失败会显示具体原因

差异对比：

```bash
# 最近两次快照的 unified diff
curl -H "Authorization: Bearer $TOKEN" \
  "http://127.0.0.1:8899/api/v2/backups/diff?device=核心A"
```

也可以在 Python 里用 `store.backups.diff("核心A")` 直接拿到 diff 文本。

**GUI 看差异**：设备清单选中一台 →「🗂 备份历史」：左侧快照列表（时间 + 大小），
右侧 diff 面板按 `+/-/@@` 着色；默认对比"最近两次"，也可 Ctrl 多选两份对比。
- **与现网对比**（v3.15）：读一次设备当前配置，和最近快照 diff——用来确认"有人手改过吗"，
  发现差异会发一条 `config.drift` 事件到事件流。

## 4. 资产盘点（一键发现）

从一个已知设备出发，自动摸清内网里有什么。

### 操作步骤

1. 「设备清单」页确保至少有一台**可登录**的设备（种子）
2. 进入「资产盘点」，选择种子设备与递归跳数（1-3，跳数越多越全面也越慢）
3. 点「🚀 一键盘点」——进度条推进中会依次：SSH 登录种子 → 采集 LLDP/CDP 邻居 + ARP 表
   → 提取内网 IP → 新邻居用**同款凭据**递归登录（depth≥2）→ 探测 22/23/830 端口
4. 结果表：每行一个资产（IP / 主机名 / 厂商推测 / 管理协议 / 发现来源 / 已知或新增）
5. 点「导入清单（新增设备）」——新发现的设备自动写入清单（凭据沿用种子，记得核对）

### 可视化

- 「拓扑」Tab：自动生成发现拓扑，**新发现节点黄色 / 已知绿色**
- 「原始输出」Tab：查看每台设备的原始采集输出（排障用）

## 5. 环路 / 漂移检测

在资产盘点的「环路/漂移」Tab，点「🔍 检测环路/漂移」：采集清单设备 MAC 表并做两级判定。

| 级别 | 判定 | 说明 |
|---|---|---|
| 🔴 高危 | **同一台设备 ≥2 端口学到同一 MAC** | 典型二层环路。建议：逐口拔线，观察广播速率是否下降 |
| 🟠 中危 | **同一 MAC 出现在 ≥2 台设备** | 环路或漂移；堆叠/ Trudeau 等合法场景需人工判断 |

- **MAC 漂移**：与上一轮快照自动比对——同设备换口、跨设备迁移都会告警
- 拓扑画布上，涉及环路的设备会**红圈 ⚠ 高亮**
- 点击告警行可查看详情（涉及设备与端口清单）
- 快照保存在 `netwright_snapshot_mac.json`，每轮检测后自动更新

> 提示：检测只采集 MAC 表，对设备零风险；建议在变更窗口前后各跑一轮做对比。

## 6. 控制器（意图下发）

OpenDaylight 思路的极简单机实现：**你声明意图，控制器翻译成各厂商命令**。

### 使用流程（三步防呆）

1. 选意图类型（VLAN 部署 / 端口角色 / BGP 邻居 / 静态路由 / NTP·Syslog 基线），
   表单填参数——每个字段有说明
2. 点 **① Dry-Run 预览**：控制器把意图翻译成每台设备的具体命令（不连设备），
   逐行审阅
3. 点 **② 确认下发**：弹窗确认后 SSH 下发，结果逐台展示；
   全程写入 `netwright_audit.log`（**密码永不入日志**）

厂商支持：意图会翻译成华为 VRP / 思科 IOS / 新华三 Comware / VyOS 对应命令；
不支持厂商的设备自动跳过并提示。

### 拓扑页

自 v3.9 起拓扑有了**独立工作区**（左侧「控制器 → 拓扑」）：「控制器 → 意图与策略 →
拓扑发现」标签页只保留一个跳转入口，避免两处重复渲染。

在拓扑工作区点「从设备发现」——LLDP/CDP 自动采集建图；
**台账导入的对端关系以虚线叠加**，实线 = LLDP 实测、虚线 = 台账登记。
详见 [2.1 拓扑工作区](#21-拓扑工作区控制器主视图)。

### 意图生命周期（v3.11）

Dry-Run 之后，一条意图会经历：**预演 → 下发 → 校验 →（必要时）回滚**。

| 阶段 | 发生什么 | 失败会怎样 |
|---|---|---|
| 预演 plan | 静态检查命令、风险、能否回滚，**不连设备** | 直接标 failed，不浪费设备连接 |
| 下发 deploy | 通过 CLI / RESTCONF / NETCONF 执行命令 | 任一条命令报错 → failed |
| 校验 verify | 回读 `display vlan` 等，确认意图真的生效 | 关键字段缺失 → failed |
| 回滚 rollback | 执行**确定安全**的反向命令（如 `undo vlan 10`） | 没有安全反向命令 → `rollback_blocked`，提示人工处置 |

> 回滚是"能确定才做"：端口 access/trunk 互转、BGP 邻居、管理面基线都**不会**自动回滚，
> 因为原状态只有设备知道——猜一条命令比不滚更危险。

### 运行档案页（v3.12）

「意图与策略 → 运行档案」是生命周期的操作面板：

1. 先在「意图下发」点 **Dry-Run**——此时档案已生成（状态「已预演」）
2. 切到「运行档案」，选中一条，右侧详情会显示：命令清单、反向命令、检查项、状态历史
3. 依次点 **② 下发 → ③ 校验**；校验会回读设备确认意图真的生效
4. 需要撤销时点 **↩ 回滚**；不可回滚的意图会直接弹窗说明原因（并标「⚠ 不可回滚」）

> 状态徽章：已预演 / 已下发 / ✓ 已校验 / ✖ 失败 / ↩ 已回滚 / ⚠ 不可回滚。
> 失败时详情里会写清是哪一步、什么错误，便于直接贴给厂商或写进工单。

### 事件源（v3.11）

「事件」页 →「事件源」卡片 →「启动监听」：

- Syslog：UDP **5140**（设备侧 `logging host <本机IP> port 5140`）
- SNMP Trap：UDP **1162**（`snmp-server host <本机IP> traps version 2c public 1162`）

收到的事件会进事件流；命中的设备节点在拓扑页画**琥珀色脉冲圈**（90 秒）。
端口被占用时启动会失败并提示，可在 `sdn/store.py` 的默认端口处改。

## 7. 批量巡检

1. 「批量巡检」页左侧勾选目标设备
2. 选择巡检方案（9 套）：标准 / 硬件健康 / 链路与拓扑 / 路由协议 / 安全基线 /
   VXLAN+EVPN / MPLS·SR / 堆叠与M-LAG / RoCEv2 无损 / IPv6 与过渡
3. 点「开始巡检」——并发执行（并发数可调），结果分级：
   ✓ 正常 / ▲ 告警 / ✖ 失败 / ○ 不可达（文字+颜色双通道）
4. 点行查看逐命令原始输出与异常明细
5. 「导出报告」生成 HTML 报告（含全部原始输出，已转义）

**趋势图**：页面底部 📈 折线图，每轮巡检自动记录摘要
（告警总数/失败台数/警告台数/平均耗时），多轮对比看网络劣化趋势。

**异常判定**：CPU/内存超阈值、接口错包、电源风扇故障、光功率 < -20dBm、
温度超标、Linux 失败服务/负载过高等。

> 没装 paramiko 时巡检不可用（界面会提示），其余模块不受影响。

## 12. REST API

「意图与策略 → REST API」页启动本机服务（默认 127.0.0.1:8899，**不对外监听**）。
v1 与 v2 并存：v1 面向脚本化既有功能，v2 是控制器语义接口。

### v2（控制器语义）

| 端点 | 说明 |
|---|---|
| GET `/api/v2/health` | 健康 + 统计（节点/链路/策略/事件/REST 版本） |
| GET `/api/v2/snapshot` | 一次性拉全量（拓扑 + 策略 + 事件 + 南向） |
| GET `/api/v2/topology` | 控制器图（nodes / links / stats） |
| GET `/api/v2/events?limit=50&severity=warning` | 事件流（可选级别过滤） |
| GET `/api/v2/policies` | 最近编译的策略 |
| GET `/api/v2/intents` | 意图目录 |
| GET `/api/v2/southbound` | 南向适配器与能力位 |
| POST `/api/v2/policies/compile` | 意图 → 策略（不连设备） |
| POST `/api/v2/topology/sync` | 设备清单 → 图 |
| POST `/api/v2/intents/plan` | 意图编译 + 静态预演（不连设备） |
| POST `/api/v2/intents/{deploy,verify,rollback}` | 下发 / 回读校验 / 回滚（body 传 `run_ids`） |
| GET `/api/v2/intents/runs` | 运行档案（状态、检查项、反向命令） |
| GET `/api/v2/sources` | syslog / trap 监听状态 |
| POST `/api/v2/sources/{start,stop}` | 启停事件源监听 |
| GET `/api/v2/backups?device=` | 备份总览 / 某台设备的历史快照 |
| GET `/api/v2/backups/diff?device=&old=&new=` | 两次快照的 unified diff |
| POST `/api/v2/backups` | 触发备份（`device_hosts` 可限定，单次上限 50 台） |

**鉴权（v3.11 起）**：除 `/api/v2/health` 外，所有 v2 请求都要带

```
Authorization: Bearer <token>
```

token 在「意图与策略 → REST API」页查看/复制/轮换（首次启动自动生成，存在设置文件里）。
v1 的写接口（`/api/apply`、`/api/dry-run`）同样需要 token；读接口保持开放便于脚本摸底。

### v1（兼容）

| 端点 | 说明 |
|---|---|
| GET `/api/health` | 健康检查 |
| GET `/api/devices` | 设备清单（密码打码） |
| GET `/api/intents` | 意图目录与表单字段定义 |
| GET `/api/topology` | 最近一次发现的拓扑 |
| POST `/api/dry-run` | 意图 → 命令计划（不连设备） |
| POST `/api/apply` | 真实下发（**必须显式 `"confirm": true`**） |

示例：

```bash
curl http://127.0.0.1:8899/api/v2/snapshot
curl -X POST http://127.0.0.1:8899/api/v2/policies/compile -H "Content-Type: application/json" \
  -d '{"intent_key":"vlan_deploy","params":{"vlans":"10,20"}}'
```

## 13. 数据文件与安全

| 文件 | 内容 | 安全 |
|---|---|---|
| `netwright_devices.json` | 设备清单 | 密码 DPAPI 加密 |
| `netwright_settings.json` | 主题/端口等偏好 | 无敏感信息 |
| `netwright_audit.log` | 意图下发审计 | 密码不入日志 |
| `netwright_controller.json` | 控制器拓扑与策略快照 | 无凭据（只有设备名/端口/链路） |
| `netwright_history_inspection.jsonl` | 巡检趋势摘要 | 无凭据 |
| `netwright_snapshot_mac.json` | MAC 表快照 | 无凭据 |
| `backups/<设备>/*.cfg` | 配置快照（v3.12） | **含设备配置，可能有机密**：注意备份目录权限 |
| `presets.json` / `profiles.json` | 命令预设/连接档案 | 密码明文（旧机制） |

- **导出 CSV 默认不含密码**；要备份凭据请复制 `netwright_devices.json`（DPAPI 密文）
- 请勿把含真实凭据的数据文件提交到公开仓库
- SSH 巡检/端口扫描只用于**自己管理或获得授权的网络**

## 14. 常见问题

**Q：巡检按钮提示缺 paramiko？**
A：`pip install paramiko` 后重启程序。

**Q：界面会不会卡？自动刷新会不会很吃 CPU？**\nA：v3.16 起做了三处优化：设备清单在数据没变时**跳过整表重建**；拓扑画布把网格单独成层，\n悬停/缩放只重画边和节点；备份查询只读最新一份并缓存摘要。几百台设备下 10 秒刷新基本无感。\n\n**Q：页面上的数字一直不变，是不是卡了？**
A：先看顶栏的「上次刷新时间」。默认每 10 秒自动刷新；如果你关掉了「自动 10s」，
按 `F5` 手动刷新。拓扑页的发现/巡检进行中会显示"发现中…"，此时自动刷新会暂停。

**Q：第一次打开全是空的，不知道点哪？**
A：右上角「? 引导」→「载入演示数据」，30 秒就能看到完整界面；看完可一键清除。

**Q：设备加了但拓扑是空的？**
A：拓扑来自两个来源：① 台账 CSV 里的 `对端设备/接口` 列（虚线）；② 设备的 LLDP/CDP
实测（实线）。只填地址不填链路列时，连上设备点「从设备发现」才会有实线。

**Q：协议选了 telnet，重启后变回 ssh？**
A：v3.10 已修复（旧版本 `from_storage` 漏读 `protocol` 字段）。升级后重新保存一次即可。

**Q：盘点发现的设备登录失败？**
A：递归发现沿用种子设备的凭据；不同密码的设备请导入清单后单独巡检。

**Q：环路检测提示"没有支持 MAC 表采集的设备"？**
A：Linux/VyOS 无通用 MAC 表命令，属预期；请用华为/思科/H3C/锐捷/MikroTik 设备做种子。

**Q：主题切换后界面没变？**
A：主题切换会整体重建界面（约 1 秒），若仍异常请重启程序。

**Q：Telnet 登录卡住？**
A：部分设备提示符非标；先用「单机巡检」验证账号密码，确认设备开启了 Telnet 服务。
